How to read this table

Job array: one submission that creates many tasks; each task needs the request shown ("each task: …"). Tasks start one after another as GPUs free up, so a large array keeps taking GPUs for a long time. "≤ N at once" is the array's own limit on running tasks.

Group QoS (orange badge): the account's group gets +5,000 to +8,000 priority points but may hold at most the shown number of GPUs at a time, across all its members and GPU types. "in use" is how many it holds right now; when it is at its cap, its queued tasks wait however high they rank.

Score: fair-share (account's recent usage vs. its share) + QoS bonus + waiting time (up to 1,000 after 14 days) + size (1,000 for everyone). Higher starts first. Status: runnable = only waiting for priority or resources; blocked = held back by a cap or a deferred start; never = cannot run as submitted (e.g. time limit over the partition maximum).

Planner: when this job would start if every job ahead of it ran to its time limit / to its user's typical run time. Hover a row for a plain-English summary.
